From softmax to linear attention

Step 1 · softmax attention

exp couples q to every stored ki → keep all keys and values · O(n²)

Step 2 · swap the kernel

replace the kernel with one that factorizes — a replacement, not an approximation (a different model, retrained)

Step 3 · regroup

regroup: the query leaves both sums — the brackets no longer depend on q

Step 4 · keep running sums

running sums: constant-size state, one write + one read per token, O(n) total · S ∈ ℝd×d = 64×64 per head · boxed = the unnormalized form used here

the swap buys cost: no growing KV cache, no per-token slowdown — a fixed 64×64 S and one write + one read per token. the risk is quality — that's what the experiments test

o = attention output (previous slide) · q, k, v = query / key / value · d = key dim · = outer product ("k ⊗ v") · S = the memory · z = the normalizer

σ = the sigmoid (logistic function) · any score → a fraction
why squash at all?
a decay rate must be a fraction: ×1.3 explodes the memory, ×(−0.5) flips its sign. σ bends the whole real line into (0,1), so every dial is a valid "how much to keep".

the wiring is what costs parameters: 768·64 = 49,152 per head × 12 heads × 12 layers = 7,077,888  ·  the static twin deletes Wg and keeps only the 64 dials: 64 × 12 × 12 = 9,216

Takeaways

  • Correct, don't accumulate. The delta rule is the strongest observed factor — top 4 in every cell, at every tested scale.
  • Many timescales need the eraser. Channel-wise decay helps only with corrective writes (18M, both corpora; within-delta it persists at 125M on WikiText-103).
  • Forgetting needn't watch the text. 9,216 static dials matched a ~7M-parameter data-dependent gate, at these scales.

limits: ≤125M, 3 seeds, fixed budget, no retrieval benchmarks · code: pure PyTorch, every seed reported

Future work

  • Scale. Rerun the cube at 500M–1B: do the delta divide and the static parity hold?
  • Retrieval. Long-range recall (needle-in-a-haystack) — the length results here are stability checks only.
  • Speed. Chunkwise kernels for the static gate (the decay blocks precompute) — close the wall-clock gap.
  • Theory. A formal account of the interference story behind Finding 2.

Backup · Slow memory, fast memory — and what softmax was buying

two slow-vs-fast axes — don't mix them
1 · when is it written? MLP weights = slow memory: written by training, frozen at inference. S = fast memory: written token by token by the current context, wiped after the sequence.
2 · how fast is it forgotten? inside S, channel-wise decay gives every row its own speed: γ = 0.368 forgets within a token · γ = 0.996 remembers ≈ 163 tokens — one state, a whole spectrum of timescales.
what softmax was buying
softmax = a soft argmax: scores → positive weights that sum to 1, keys compete, the best match wins sharply → near-exact retrieval.
the price: exp ties q to every stored k → keep the whole KV cache. drop it → everything factorizes into S at constant cost, but matching becomes linear and blurry — similar keys interfere.

the trade: a constant-size S gives up sharp retrieval — corrective (delta) writes win some of it back when keys collide

Backup · What each side costs — training vs inference

n = sequence length · d = head dimension (64 here) · the state S is d×d, per head

softmax attentionlinear attention
training · compute O(n²·d) — quadratic in n: the QKᵀ matrix O(n·d²) recurrent — linear in n but sequential · chunkwise kernels keep it linear AND parallel
training · memory O(n²) attention matrix — FlashAttention cuts it to O(n), but compute stays quadratic O(d²) state — no n² matrix at all
inference · compute/token O(n·d) — attend to every cached key: grows with context O(d²) — constant, whatever the context
inference · memory O(n·d) KV cache — grows token by token O(d²) state — never grows

softmax: cost scales with how much you've seen · linear: cost is fixed no matter how much you've seen

— paid for by compressing all history into one lossy d×d state
